# Hard eval set + question filters (2026-10-20)

**Question:** where does the agent still fail, now that the 1c eval saturates (~0.95)? And
does pulling the source and date out of a question help?
**Answer:**
- **Short keyword queries are fine:** 0.90 found in the top 5.
- **Details deep in an article are the real gap:** 0.50.
- **The new rule-based filter parser fixes source/date questions** for automatic
  retrieval: constraint compliance rises from 0.46 to 0.98, strict precision from 0.29 to
  0.44. The full agent already got there through its tools, so its scores barely move.
- **A step-limit crash was found and fixed:** 4/95 questions raised `GraphRecursionError`
  to the user; now 0.
- **Update 2026-10-21, passage rescue:** the deep-detail gap is now 0.70 (from 0.50),
  entity_number 0.95 (from 0.85), for $0, with topical questions unchanged. See
  [Passage rescue](#passage-rescue-2026-10-21) below.

## The set (`ai_agents/eval/hard_eval.py`, 95 questions)

Generated by `gpt-4.1-mini` (not the agent's model) from seed articles in `obt_articles`,
spread round-robin over the 10 sources. Questions are in `ai_agents/eval/hard_eval_questions.json`;
4 were hand-rewritten (`"edited": true`) because they only made sense to someone who had
read the article ("the author", "Ông…").

| Category | n | What it tests | Score |
|---|---|---|---|
| `keyword_short` | 20 | 2–5 search words ("SJC vàng miếng") | seed article in top 5 / first |
| `entity_number` | 20 | an exact name + number from the lead | same |
| `deep_detail` | 20 | a detail from body chars 3,000–4,800 (vectors see ~1,500) | same |
| `time_relative` | 15 | "this week", "mấy ngày qua", "latest" about 0–3-day-old stories | judge: strict = on topic **and** in the window |
| `filtered` | 20 | a named source and/or month / year | judge + programmatic source/date check |

Systems:
- `agent_default`: production automatic retrieval, now with the parser
- `agent_noparse`: the same without the parser, i.e. before
- `v2_dense`: no recency rule, no parser
- `keyword`: the keyword leg alone
- `agent_e2e`: the whole agent (gpt-5.4-mini + tools), scored on the URLs its answer cites
- `agent_e2e_before`: `agent_e2e` before the parser and the step-limit fix

The judge is `gpt-4.1-mini`, given today's date, the source and the publication date. For
the agent, "found" means the seed's URL is cited. That is a **lower bound**: it often
answered correctly from another outlet's copy of the same story.

## What it says

1. **Short keyword queries are not a problem** for dense search (0.90). The keyword leg alone
   is far worse even on its home turf (0.25), which confirms dropping it from automatic
   retrieval.
2. **Deep details are the main gap:** 0.50 found@5, against 0.85–0.90 elsewhere. The
   article vectors embed title + ~1,500 characters, so a detail on character 4,000 is
   invisible to them. The agent's `get_article` / full-text keyword tools only partly
   compensate (it cited the seed 0.30 of the time). Addressed 2026-10-21 by the passage
   rescue below (chunk vectors were costed and deferred).
3. **Filters: a big win for automatic retrieval, little for the full agent.** With
   `query_filters`, 98% of retrieved results match the stated source and period (46%
   before). The agent already applied filters through `search_news` tool calls, so its end
   scores stay level (0.67 vs 0.69, noise). Now the first retrieval is already right, before
   any tool call.
4. **Time-relative questions stay weak in strict terms** (0.24 automatic, 0.40 agent),
   though lenient precision is fine (0.75 / 0.91). Only 1–2 questions per phrase, so no
   per-phrase conclusion. Two obviously missing phrasings were added to `recency_days`
   afterwards ("past / last few days", "mấy ngày qua", "những ngày qua"…); that change is
   not re-measured here.
5. **The step limit was a user-facing crash.** 4/95 questions made the agent loop on tools
   until LangGraph's recursion limit raised `GraphRecursionError`. Now `ask()` catches it,
   answers once from what was found (no tools), and stores a valid history: the dangling
   tool call gets a "not run" result. A follow-up in the same thread works (forced test
   with `recursion_limit=4`).

## The filter parser (`core/text.py`)

`query_filters(query, today)` returns `{"source": [...], "start_date", "end_date"}`.
- **Sources:** a pattern list, most specific first ("VnExpress International" →
  `vnexpress_en`; "VnExpress" → both editions). "tuổi trẻ" / "thanh niên" are also
  ordinary words ("youth", "young people"), so they need the capitalised name or "báo"
  in front.
- **Periods:** "tháng 8/2026", "tháng 8 năm 2026", "August 2026", "in / during August" (a
  bare "may" is a verb), "this year / năm nay", "last year / năm ngoái", "in / năm 2024".
- **Applied** by `hybrid_retrieve` as a **hard** Pinecone filter (`$in` for several
  sources) when the caller gave none. If it finds nothing, it is dropped
  (`stats["parsed_filters_dropped"]`). The keyword leg gets the dates, plus the source when
  it is a single one. Explicit tool filters win.
- **Caveat:** written after seeing the set's 20 filtered questions (it parses all 20
  exactly), so a fresh set will find some phrasings it misses. It was checked against
  negatives too ("Tuổi trẻ ngày nay…", "What may happen…", "Giá vàng tháng này").

## Passage rescue (2026-10-21)

**Question:** can the deep-detail gap be closed without paying for chunk vectors?
**Answer:** mostly. 0.50 → 0.70 found@5 for $0 in embeddings, ~25 MB of BigQuery and
~1 s per question.

**Where the seed sits in v2 dense** (no filters), found@k:

| | @5 | @10 | @20 | @30 | @50 | @100 |
|---|---|---|---|---|---|---|
| keyword_short | 0.90 | 0.95 | 0.95 | 0.95 | 0.95 | 1.00 |
| entity_number | 0.85 | 0.90 | 0.95 | 0.95 | 1.00 | 1.00 |
| deep_detail | 0.55 | 0.65 | 0.70 | **0.80** | 0.80 | 0.85 |

So most deep-detail seeds are retrieved, just ranked too low: a reranker that reads the
whole body can lift them, and 0.80 is its ceiling at a pool of 30.

**Design (`core/passages.py`, `core/articles.get_bodies`):** fetch the top 30 dense hits'
full bodies; split each into 500-char passages (step 250, title prefixed); score every
passage with BM25 against the question (idf over the pool, syllable bigrams for Vietnamese,
time words like "this week" / "mới nhất" dropped); keep the dense top 4, fill the remaining
slots with the other articles in order of their best passage. Each article's best passage is
appended to its context text, so the LLM sees the detail too. `AGENT_PASSAGE_POOL` (30, 0 =
off) and `AGENT_PASSAGE_KEEP` (4). On any failure it keeps the dense order.

**Variants** (offline replay on the production 30-deep pool; found@5 / hit@1 for known
items, strict / lenient / constraint ok for topical):

| Variant | keyword_short | entity_number | deep_detail | time_relative | filtered |
|---|---|---|---|---|---|
| dense (no rerank) | 0.90 / 0.65 | 0.85 / 0.65 | 0.50 / 0.30 | 0.23 / 0.76 / 0.52 | 0.44 / 0.69 / 0.98 |
| RRF, passage weight 2 | 0.90 / 0.80 | 0.95 / 0.65 | 0.70 / 0.45 | **0.15 / 0.57 / 0.37** | 0.38 / 0.71 / 1.00 |
| RRF, weight 0.5 | 0.95 / 0.80 | 0.90 / 0.60 | 0.55 / 0.40 | 0.17 / 0.68 / 0.49 | 0.44 / 0.73 / 1.00 |
| keep top 3, rescue rest | 0.90 / 0.65 | 0.95 / 0.65 | 0.70 / 0.30 | 0.23 / 0.76 / 0.53 | 0.40 / 0.69 / 0.99 |
| **keep top 4, rescue rest** (chosen) | 0.90 / 0.65 | 0.95 / 0.65 | 0.70 / 0.30 | 0.21 / 0.77 / 0.53 | 0.44 / 0.71 / 0.98 |
| keep top 2, rescue rest | 0.90 / 0.65 | 0.95 / 0.65 | 0.70 / 0.30 | 0.19 / 0.67 / 0.45 | 0.37 / 0.68 / 0.99 |

A full rerank (reciprocal rank fusion of dense and passage rank) also gives the known-item
gains and better hit@1, but it pushes older keyword-matching articles above recent on-topic
ones, so time-relative questions drop. One rescue slot keeps every known-item gain and leaves
topical scores at the dense level (differences ≤ 0.02, noise at n = 15–20). The official
re-run (`agent_default` vs same-day `agent_nopassage`) matches the replay exactly. Latency
p50 0.9 → 1.8 s, p90 2.3 → 5.3 s.

**Body storage:** `vectors.article_bodies` (bucket, article_id, content_hash, body_text,
saved_at), integer-range partitioned on a hash bucket of article_id (3,000 buckets),
clustered on article_id, append-only (latest `saved_at` wins). Measured per 30-id lookup:
`obt_articles` (month partitions) ~1.3 GB, a copy clustered on article_id 2.0–2.5 GB
(scattered ids hit every block), the hash-bucket table **25 MB**. `embed_articles.py` writes
each new article's body just before its vector (free load job); `embed_articles.py bodies
[--full]` fills gaps (backfill 2.52 GB once; windowed repair ~0.5 GB).

**Why not chunk vectors (yet):** embedding the full text of the archive is ~300M tokens
(≈ $60–70) and ~1M+ extra vectors, beyond Pinecone Starter's 2 GB (1.26 GB used): a paid
tier would break the $5–10/month budget after the trial. A recent window is cheaper ($5 for
30 days) but most hard-set seeds are older. Chunk vectors would lift the 0.80 ceiling and
stack with this rescue; a ~$1 pilot (last 7 days + new deep-detail questions on them) would
measure the gain before committing.

**End-to-end agent** (2026-10-22, `agent_e2e` with passages vs `agent_e2e_nopassage`, the
10-20 run; gpt-5.4-mini; "cited the seed" / cited it first):

| | keyword_short | entity_number | deep_detail | filtered (strict / lenient / constraint) | tool calls / q | p50 |
|---|---|---|---|---|---|---|
| before | 0.85 / 0.40 | 0.65 / 0.65 | 0.30 / 0.20 | 0.67 / 0.92 / 0.95 | 0.86 | 6.9 s |
| with passages | 0.80 / 0.40 | 0.60 / 0.60 | **0.55 / 0.40** | **0.74 / 0.96 / 1.00** | **0.41** | 5.7 s |

- The agent now cites the deep-detail article almost twice as often (0.30 → 0.55): the
  matching passage is in its context, so it answers without a `get_article` call.
- It calls tools half as often (0.86 → 0.41 per question) and answers ~1 s faster.
- keyword_short / entity_number: one question fewer each, noise at n = 20. The agent cites
  fewer articles than retrieval returns, so these stay below the retrieval numbers.
- time_relative (0.40 → 0.33 strict, constraint 0.86 → 0.65) **can't be compared**: the
  questions were written on 10-20 and re-asked on 10-22. Of the cited articles outside the
  window, 11 were newer than it (right for "this week" asked today; 2 before) and 5 older
  (7 before), so the drop is date drift, not a regression.

**Not re-measured:** the 1c set (`retrieval_eval.py`).

## Caveats

- Small groups (15–20): differences under ~0.1 are noise.
- Time-relative questions only hold on the day they were written (`asked_on` = 2026-10-20;
  the run crossed midnight in Vietnam time).
- One LLM judge, reading titles and snippets.
