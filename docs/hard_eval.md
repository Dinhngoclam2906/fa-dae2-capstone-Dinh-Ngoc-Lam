# Hard eval set + question filters (2026-10-20)

**Question:** where does the agent still fail, now that the 1c eval saturates (~0.95)? And
does pulling the source and date out of a question help?
**Answer:**
- **Short keyword queries are fine:** 0.90 found in the top 5.
- **Details deep in an article are the real gap:** 0.50.
- **The new rule-based filter parser fixes source/date questions** for automatic
  retrieval: constraint compliance rises from 0.46 to 0.98, strict precision from 0.29 to
  0.44. The full agent already got there through its tools, so its scores barely move.
- **A step-limit crash was found and fixed:** 4/95 questions raised `GraphRecursionError`
  to the user; now 0.

## The set (`ai_agents/eval/hard_eval.py`, 95 questions)

Generated by `gpt-4.1-mini` (not the agent's model) from seed articles in `obt_articles`,
spread round-robin over the 10 sources. Questions are in `ai_agents/eval/hard_eval_questions.json`;
4 were hand-rewritten (`"edited": true`) because they only made sense to someone who had
read the article ("the author", "Ông…").

| Category | n | What it tests | Score |
|---|---|---|---|
| `keyword_short` | 20 | 2–5 search words ("SJC vàng miếng") | seed article in top 5 / first |
| `entity_number` | 20 | an exact name + number from the lead | same |
| `deep_detail` | 20 | a detail from body chars 3,000–4,800 (vectors see ~1,500) | same |
| `time_relative` | 15 | "this week", "mấy ngày qua", "latest" about 0–3-day-old stories | judge: strict = on topic **and** in the window |
| `filtered` | 20 | a named source and/or month / year | judge + programmatic source/date check |

Systems:
- `agent_default`: production automatic retrieval, now with the parser
- `agent_noparse`: the same without the parser, i.e. before
- `v2_dense`: no recency rule, no parser
- `keyword`: the keyword leg alone
- `agent_e2e`: the whole agent (gpt-5.4-mini + tools), scored on the URLs its answer cites
- `agent_e2e_before`: `agent_e2e` before the parser and the step-limit fix

The judge is `gpt-4.1-mini`, given today's date, the source and the publication date. For
the agent, "found" means the seed's URL is cited. That is a **lower bound**: it often
answered correctly from another outlet's copy of the same story.

## What it says

1. **Short keyword queries are not a problem** for dense search (0.90). The keyword leg alone
   is far worse even on its home turf (0.25), which confirms dropping it from automatic
   retrieval.
2. **Deep details are the main gap:** 0.50 found@5, against 0.85–0.90 elsewhere. The
   article vectors embed title + ~1,500 characters, so a detail on character 4,000 is
   invisible to them. The agent's `get_article` / full-text keyword tools only partly
   compensate (it cited the seed 0.30 of the time). The real fix is chunk vectors for a
   recent window (backlog 1d).
3. **Filters: a big win for automatic retrieval, little for the full agent.** With
   `query_filters`, 98% of retrieved results match the stated source and period (46%
   before). The agent already applied filters through `search_news` tool calls, so its end
   scores stay level (0.67 vs 0.69, noise). Now the first retrieval is already right, before
   any tool call.
4. **Time-relative questions stay weak in strict terms** (0.24 automatic, 0.40 agent),
   though lenient precision is fine (0.75 / 0.91). Only 1–2 questions per phrase, so no
   per-phrase conclusion. Two obviously missing phrasings were added to `recency_days`
   afterwards ("past / last few days", "mấy ngày qua", "những ngày qua"…); that change is
   not re-measured here.
5. **The step limit was a user-facing crash.** 4/95 questions made the agent loop on tools
   until LangGraph's recursion limit raised `GraphRecursionError`. Now `ask()` catches it,
   answers once from what was found (no tools), and stores a valid history: the dangling
   tool call gets a "not run" result. A follow-up in the same thread works (forced test
   with `recursion_limit=4`).

## The filter parser (`core/text.py`)

`query_filters(query, today)` returns `{"source": [...], "start_date", "end_date"}`.
- **Sources:** a pattern list, most specific first ("VnExpress International" →
  `vnexpress_en`; "VnExpress" → both editions). "tuổi trẻ" / "thanh niên" are also
  ordinary words ("youth", "young people"), so they need the capitalised name or "báo"
  in front.
- **Periods:** "tháng 8/2026", "tháng 8 năm 2026", "August 2026", "in / during August" (a
  bare "may" is a verb), "this year / năm nay", "last year / năm ngoái", "in / năm 2024".
- **Applied** by `hybrid_retrieve` as a **hard** Pinecone filter (`$in` for several
  sources) when the caller gave none. If it finds nothing, it is dropped
  (`stats["parsed_filters_dropped"]`). The keyword leg gets the dates, plus the source when
  it is a single one. Explicit tool filters win.
- **Caveat:** written after seeing the set's 20 filtered questions (it parses all 20
  exactly), so a fresh set will find some phrasings it misses. It was checked against
  negatives too ("Tuổi trẻ ngày nay…", "What may happen…", "Giá vàng tháng này").

## Caveats

- Small groups (15–20): differences under ~0.1 are noise.
- Time-relative questions only hold on the day they were written (`asked_on` = 2026-10-20;
  the run crossed midnight in Vietnam time).
- One LLM judge, reading titles and snippets.
